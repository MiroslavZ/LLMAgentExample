# MCP для файлов проекта

Локальный сервер предоставляет чтение, поиск, создание и редактирование файлов
фиксированного проекта, а также прежний инструмент `git_branch`.
Использует установленный SDK `mcp==2.2.0`, транспорт **Streamable HTTP** и
слушает только `http://127.0.0.1:8001/mcp`. Токен не требуется.

## Запуск

Из корня проекта в PowerShell, в отдельном терминале:

```powershell
.\venv\Scripts\python.exe -m LocalMCPServer.server
```

Существующие окружения и зависимости используются без изменений. При создании
отдельного окружения установите зависимости из `LocalMCPServer/requirements.txt`.
Прежний запуск `.\LocalMCPServer\venv\Scripts\python.exe .\LocalMCPServer\server.py`
также поддерживается. Git в `PATH` нужен только инструменту `git_branch`;
файловые операции работают с обычной папкой. Остановка — `Ctrl+C`.

По умолчанию проектом является родитель папки `LocalMCPServer`, независимо от
текущего рабочего каталога. Можно закрепить другой корень проекта и порт
при запуске:

```powershell
.\venv\Scripts\python.exe -m LocalMCPServer.server --project-root C:\Projects\Example --port 8002
```

Проверка из основного окружения проекта:

```powershell
.\venv\Scripts\python.exe -m llm_agent.mcp_client --url http://127.0.0.1:8001/mcp --token-env=
```

Настройка MCP-подключения: URL `http://127.0.0.1:8001/mcp`, поле переменной
окружения с токеном пустое. Порт 8001 позволяет запускать сервер одновременно
с существующим MCP-сервисом на порту 8000.

## Работа через существующего агента

В веб-чате добавьте подключение выше, включите **Использовать в чате** и выберите
модель с поддержкой tool calling. Опишите цель обычным сообщением. Агент получает
схемы через MCP, сам ищет и читает файлы, затем вызывает создание или редактирование.
Новый цикл агента, RAG и отдельный интерфейс не нужны. Аргументы и результаты
каждого вызова сохраняются в существующем журнале диалога.

[Готовый пример с двумя целями и восстановлением исходного состояния](../examples/file_assistant/README.md)
работает в отдельной папке `data/file-assistant-demo/project/`.

## Файловые инструменты

Все пути относительные к `--project-root`. Аргументы дополнительно проверяются
сервером по JSON Schema, в том числе при обращении другим MCP-клиентом.

| Инструмент | Аргументы | Результат |
|---|---|---|
| `list_files` | `path="."`, `pattern="*"`, `limit=100`, `offset=0` | Пути файлов, следующая страница, полнота обхода |
| `search_text` | `query`, те же параметры области/страницы, `case_sensitive=true` | Совпадающие строки: `path`, `line`, `text` |
| `read_file` | `path`, `start_line=1`, необязательный `end_line` | Точный текст диапазона и SHA-256 всего файла |
| `create_file` | `path`, `content` | Сохранённый файл, `changed`, SHA-256 и diff |
| `edit_file` | `path`, `old_text`, `new_text`, `expected_sha256` | Результат точечной замены с diff |

`search_text` ищет буквальную строку; регулярные выражения и анализ связей кода
не выполняются. `pattern` — fnmatch-маска имени или пути относительно `path`;
обход рекурсивный. Например, `*.py` находит Python-файлы и во вложенных каталогах.
Номера строк начинаются с 1; совпадение возвращается один раз на строку.

Чтение возвращает точный `content` для редактирования и `numbered_content` с номерами
тех же строк для анализа и ссылок. Также возвращаются `total_lines`, фактически
выданные `start_line`/`end_line`, `sha256`, `truncated` и `next_start_line`.
При усечении дочитайте диапазон с `next_start_line`. Явно заданный короткий диапазон
не считается усечением. Для пустого файла `total_lines=0`, `content=""`.

Перед `edit_file` прочитайте файл и передайте его `sha256` в `expected_sha256`.
`old_text` должен точно совпадать с одним фрагментом, включая переводы строк.
Нулевое, неоднозначное совпадение или устаревшая версия дают ошибку без изменения
файла. При нескольких последовательных правках используйте новый `sha256` из
результата предыдущей записи. Если старый и новый текст равны, `changed=false`.

`create_file` не перезаписывает существующий путь. Недостающие родительские
каталоги создаются внутри корня. Запись публикуется через временный файл;
редактирование сохраняет остальные байты, включая CRLF, BOM и отсутствие конечного
перевода строки. Проверка версии повторяется перед заменой. Это не транзакция
для нескольких файлов и не блокировка редакторов других процессов.

Diff строится сервером из фактического старого и нового текста, включая новые
файлы без Git. Он возвращается вместе с `path`, `changed`, `sha256`,
`bytes_written` и `diff_truncated`. Изменения сразу сохраняются на диск;
отдельного этапа подтверждения и автоматического commit/push нет.

## Границы и лимиты

Единая проверка путей применяется и к прямому чтению/записи, и к каждому файлу
поиска. Запрещены выход из корня, абсолютные пути, Windows ADS и имена устройств,
symlink/junction. Исключаются `.git`, виртуальные окружения, `node_modules`,
кэши, служебные папки, `.env*`, ключи, секретные файлы данных, локальные базы и логи.
Обычные исходники `tokens.py`, `credentials.py` разрешены. Полный список находится
в `project_files.py`; содержимое файлов на наличие секретов не классифицируется.
Git и `.gitignore` для обхода не используются.

- Только текст UTF-8, не более 256 KiB на файл; бинарные файлы отклоняются.
- До 200 элементов на страницу; чтение, страницы и diff ограничены примерно
  6000 символами каждый. Совпадающая строка поиска сокращается до 500 символов
  с признаком `text_truncated`; целый фрагмент можно прочитать через `read_file`.
- Если отдельная строка не помещается в лимит чтения или сериализованного ответа,
  возвращается `line_too_long`, без потери её хвоста. Нумерованное представление
  учитывается в бюджете ответа; продолжение доступно через `next_start_line`.
- Обход ограничен 20 000 объектами и глубиной 64, поиск — 8 MiB прочитанных данных.

Для списка и поиска используйте `next_offset`, пока он не станет `null`.
`scan_complete=false` означает, что нужно сузить область; `skipped_files`
содержит причины пропусков. `total_matches` — число совпадающих строк, а не
семантических использований символа. При неполном обходе итоговое количество
не объявляется полным. Ограничения путей не являются ОС-песочницей против
злонамеренного процесса, одновременно подменяющего файлы.

Ошибки имеют `isError: true` и `structuredContent` с `code` и `error`.
Успешные результаты также возвращаются в `structuredContent` и дублируются
JSON-текстом в `content`. Агент использует структурированную версию без дублирования.

## Контракт git_branch

`git_branch` вызывается без аргументов (`{}`). Результат возвращается как
`structuredContent` и дублируется JSON-текстом в `content`:

```json
{
  "project_root": "C:\\Projects\\Example",
  "branch": "main",
  "commit": "6917ffa89734e5c696d341c6a0ccb71c7e41c92e",
  "detached": false
}
```

- `project_root` — абсолютный разрешённый путь к настроенному корню проекта.
- `branch` — имя текущей ветки; `null` при detached HEAD.
- `commit` — полный SHA текущего коммита; `null` до первого коммита.
- `detached` — `true`, когда HEAD указывает непосредственно на коммит.

Состояние читается заново при каждом вызове, поэтому переключение ветки видно
без перезапуска сервера. Недоступный Git, таймаут и папка, которая не является
корнем Git-репозитория, возвращают `isError: true` с понятным сообщением.
Ошибки не подменяются вымышленной веткой. Подкаталоги репозитория и bare
репозитории не поддерживаются: передайте корень рабочего дерева.

Инструмент не принимает путь, shell-команду или дополнительные аргументы.
Все Git-команды фиксированы, запускаются без shell и ограничены таймаутом
5 секунд на команду. Переменные `GIT_*` из окружения не могут переключить
репозиторий. Этот инструмент не изменяет файлы, ветки или индекс и не передаёт клиенту
stderr Git.

## Проверка

Из основного окружения проекта:

```powershell
.\venv\Scripts\python.exe -m unittest tests.test_project_files tests.test_project_mcp_server tests.test_project_files_agent -v
```

Тесты работают во временных папках: проверяют реальные изменения, ограничения,
пагинацию, конфликты и Git. HTTP-проверки используют настоящий локальный сервер
и `llm_agent.mcp_client`. Интеграционный тест выполняет два сценария через
существующий `Agent` и MCP; подставляется только ответ LLM. Он проверяет механику,
а не качество живой модели. Нужны разрешения на localhost и атомарные файловые
операции; symlink-проверка пропускается, если Windows не разрешает создание ссылки.
