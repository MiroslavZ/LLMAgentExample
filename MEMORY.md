# Модель памяти агента

Реализация дня 11 сохраняет существующие стратегии контекста и добавляет
явную память. Один диалог соответствует одной задаче. Конечный автомат,
персонализация по нескольким профилям и проверка инвариантов — следующие этапы
из TASKS.md; сейчас они не реализованы.

## Слои и правила записи

| Слой | Что содержит | Кто сохраняет | Область и хранение |
|---|---|---|---|
| Краткосрочная | Сообщения текущего диалога, локальные facts/summary, статистика | Агент сохраняет успешные обмены; выбранная стратегия обрабатывает историю | JSON диалога; в веб также хранится полная лента, включая ошибки |
| Рабочая | Цель, входные данные, ограничения, промежуточный результат задачи | Пользователь явно выбирает `working`, ключ и значение | Таблица `working_memory`, отдельный `scope` каждой задачи |
| Долговременная | Общие сведения пользователя: предпочтения, подтверждённые решения, знания | Пользователь явно выбирает `long_term`, ключ и значение | Таблица `long_term_memory`, единый словарь внутри одного файла базы |

Пример: фраза «делаем отчёт к пятнице» остаётся в диалоге. Явное сохранение
`working / deadline = пятница` делает срок доступным после обрезки истории.
`long_term / language = русский` доступно и в следующей задаче.
Предложение ассистента не становится подтверждённым решением автоматически.
Просьба «запомни» в обычном чате также не вызывает запись: используйте редактор
или CLI-команду. Это выбранная политика наполнения памяти для данного этапа.

Рабочие и долговременные записи — непустые строковые пары ключ–значение.
Повторное сохранение того же ключа заменяет значение в выбранном слое.
У долговременной памяти нет категорий и вложенных словарей. Удаление затрагивает только
выбранную запись. Данные из одного слоя не копируются в другой автоматически.
При необходимости переноса пользователь сохраняет запись в целевом слое.

## Хранение и жизненный цикл

- Веб: `data/conversations/<id>.json` содержит краткосрочный слой; историческое
  поле `working_context` обозначает **контекст стратегии**, а не новую рабочую
  память. Формат старых файлов остаётся совместимым.
- CLI: краткосрочный слой остаётся в `--history` (по умолчанию `history.json`).
  В режиме веток checkpoint содержит историю, facts/summary и статистику.
- SQLite: по умолчанию `data/conversations/memory.sqlite3`, без дополнительных
  зависимостей. Записи изменяются транзакционно; разные процессы и вкладки
  могут добавлять разные ключи без перезаписи всей памяти.
  Схема базы — версия 2; переноса из прежнего формата с категориями нет.
  Для работы после прежней версии нужна новая база памяти. Старый файл
  автоматически не изменяется и не удаляется; JSON-диалоги совместимы.
- Веб-`scope` — ID диалога. CLI-`scope` — абсолютный путь истории и активная
  ветка. Рабочая память CLI и веб изолирована, долговременная при общей БД общая.
- Новый диалог / новый путь истории / новая ветка начинают с пустой рабочей
  памятью. Возврат к существующей задаче восстанавливает её записи. Checkpoint
  и ветвление не копируют явную рабочую или долговременную память.
- Удаление веб-диалога очищает его рабочие записи и сохраняет долговременные.
  Очистка рабочей памяти не удаляет историю; прежние сведения могут оставаться
  в сообщениях и facts/summary. Для новой задачи создайте новый диалог.
- `--data-dir` в веб меняет каталог диалогов и расположение базы. CLI можно
  подключить к той же базе через `--memory-db <каталог>/memory.sqlite3`.

Срок жизни слоя определяет область его использования, а не хранение в RAM:
даже краткосрочная память текущего диалога переживает перезапуск. База общая
для одного локального пользователя; разделения по аккаунтам пока нет.
Для согласованной резервной копии остановите приложение и скопируйте каталог
данных, а также отдельные CLI-истории, если они используются.

## Сборка запроса

1. Выбранная стратегия готовит текущий диалог: вся история, окно, локальные
   факты + окно, summary + хвост или активная ветка.
2. Веб-сервис/CLI загружает снимок явной памяти выбранной задачи и передаёт его
   `Agent(memory=...)`.
3. После применения стратегии агент добавляет отдельные справочные блоки
   `<long_term_memory>` и `<working_memory>` перед сообщениями диалога.
4. Последним идёт текущий запрос. В режиме мета-промпта оба этапа используют
   один снимок явной памяти.

Пустые блоки не добавляются. История, системный промпт, facts и summary не
перезаписываются текстом этих блоков. Извлечение facts и сжатие истории не
получают явные слои памяти. Ответ модели сохраняется в краткосрочный слой
обычным образом и, разумеется, может упоминать сведения из памяти.

В инструкции к блокам явно обозначено: записи — справочные данные, системные
правила остаются в силе; явные записи важнее автоматически извлечённых
facts/summary, а данные текущей задачи уточняют общие сведения. Это указание
модели, не программная проверка инвариантов. Текущие уточнения пользователя
не обновляют хранилище без отдельного сохранения.

В запрос включаются все явные записи выбранной задачи и общей долговременной
памяти. На этом шаге нет поиска релевантных знаний, TTL и автоматического
сжатия этих слоёв; размер контекста растёт с объёмом сохранённых записей.
При прямом использовании Python загрузите новый `store.snapshot(scope)` для
нового агента после изменения памяти: `Agent` работает с переданным снимком.

## Использование

В браузере кнопка «Память агента» открывает просмотр текущего диалога и
редакторы двух явных слоёв. Выберите слой, заполните ключ и значение, сохраните.
Управление памятью доступно
без API-ключа. Изменения применяются к следующему запросу; уже запущенный
запрос продолжает использовать свой снимок.

```shell
# Эти команды не требуют API_KEY и не вызывают модель
python main.py --memory-set working goal "Подготовить отчёт о продажах"
python main.py --memory-set working deadline "пятница"
python main.py --memory-set long_term language "русский"
python main.py --memory-set long_term storage "SQLite"
python main.py --memory-show

# Явная память останется в запросе даже при окне из одного сообщения
python main.py --strategy window --window-size 1 --user "Что нужно сделать и к какому сроку?"

# Отдельная задача: её рабочая память пуста, долговременная доступна
python main.py --history ./another-task.json --memory-show

# Удаление записи или очистка только рабочей памяти
python main.py --memory-delete working deadline
python main.py --memory-delete long_term storage
python main.py --memory-clear-working
```

## Проверка результата

```shell
python -m unittest discover -s tests -v
```

Тесты проверяют отдельное хранение, изоляцию задач, единый долговременный словарь, обновление и
удаление ключей, перезапуск, ошибки БД и взаимодействие со стратегиями и
мета-промптом. В отдельном сценарии подставная модель формирует ответ по
фактически переданному контексту: без записи задача неизвестна, с записью
появляется ответ на её основе даже после обрезки диалога. Такая проверка
подтверждает путь данных до модели, но не оценивает качество ответов DeepSeek.
Все автоматические проверки выполняются без внешнего API.

Для ручной проверки с моделью создайте два пустых диалога со стратегией
«Скользящее окно», размер 1. В первом сохраните рабочие `goal` и `deadline`,
во втором оставьте рабочую память пустой. Задайте одинаковый вопрос
«Какая у меня текущая задача и срок?». Первый запрос содержит сохранённые
сведения, второй — нет. Затем сохраните долговременную запись о языке,
создайте третий диалог и проверьте её в редакторе и ответе. Перезапустите
сервер: записи должны остаться. Конкретный текст ответа зависит от модели.
