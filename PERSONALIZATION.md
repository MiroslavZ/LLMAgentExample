# Персонализация — день 12

Профиль задаёт, **как агент отвечает конкретному пользователю**. Это отдельная
конфигурация поведения, которую пользователь создаёт и выбирает явно.
Память хранит накопленные сведения, а стратегии контекста решают, какую часть
переписки передать модели. Эти механизмы работают совместно.

## Поля профиля

| Поле | Назначение |
|---|---|
| `id` | Стабильный ID: 1–64 латинские буквы, цифры, `_` или `-` |
| `name` | Обязательное название для выбора в интерфейсе |
| `address` | Как обращаться к пользователю |
| `language` | Язык ответов |
| `style` | Тон, подробность, уровень объяснений |
| `format` | Структура ответа, необходимость примеров и кода |
| `constraints` | Ограничения: стек, зависимости, бюджет и т. п. |
| `context` | Роль, опыт, проект и другие исходные сведения пользователя |

Все значения — строки; поля, кроме `id` и `name`, необязательны. Пустое поле
не задаёт предпочтения. JSON с неизвестными полями или неверными типами
отклоняется. Примеры: [новичок](examples/profiles/beginner.json) и
[опытный разработчик](examples/profiles/engineer.json).

## Браузер

Запустите `python -m llm_agent.web`. В настройках диалога доступен выбор
профиля, а кнопка «Профили пользователя» открывает управление профилями.
Создайте профиль, заполните предпочтения, сохраните и выберите его для диалога.
Для отключения персонализации очистите поле выбора профиля.

Выбор применяется к следующим сообщениям, сохраняется после перезапуска и
может меняться в уже начатом диалоге. Новый диалог начинает без профиля.
Редактирование общего профиля влияет на следующие запросы всех диалогов,
которые его выбрали. Уже выполняющийся запрос использует прежний снимок.
Конфликт редактирования из двух вкладок отклоняется: откройте профиль заново.
Удаление профиля снимает его выбор во всех диалогах.

## CLI

Из корня проекта, без обращения к API:

```shell
python main.py --profile-import examples/profiles/beginner.json
python main.py --profile-import examples/profiles/engineer.json
python main.py --profile-list
python main.py --history beginner-history.json --profile beginner
python main.py --history beginner-history.json --profile-show
```

Импорт создаёт или полностью заменяет профиль с тем же `id`, но сам не выбирает
его. Для изменения отредактируйте исходный JSON и импортируйте повторно.

После выбора достаточно обычного запроса — повторять профиль не нужно:

```shell
python main.py --history beginner-history.json --user "Как добавить кэширование результатов медленной функции?"
python main.py --history beginner-history.json --user "Какие риски у этого подхода?"
python main.py --history engineer-history.json --profile engineer --user "Как добавить кэширование результатов медленной функции?"
python main.py --history engineer-history.json --user "Какие риски у этого подхода?"
```

Снять выбор или удалить профиль:

```shell
python main.py --history beginner-history.json --profile-clear
python main.py --profile-delete beginner
```

`--profiles-db PATH` выбирает отдельную базу. По умолчанию это `profiles.sqlite3`
рядом с `--memory-db`; при стандартных параметрах CLI и веб видят одни профили.
Выбор независим для каждого пути истории и каждой ветки (`--strategy branch`).
Новая ветка начинает без профиля; checkpoint не копирует конфигурацию.

## Python

```python
from llm_agent.agent import Agent
from llm_agent.profile import ProfileStore, UserProfile

profiles = ProfileStore("data/conversations/profiles.sqlite3")
profile = UserProfile(
    id="personal", name="Мой профиль", language="Русский",
    style="Кратко и деловым тоном", format="Нумерованный список",
    constraints="Python, минимум зависимостей",
    context="Разработчик учебного ИИ-агента",
)
profiles.save(profile)
agent = Agent(token="ваш_токен", profile=profiles.get("personal"))
try:
    print(agent.request("Предложи следующий шаг").content)
finally:
    agent.close()
```

`Agent` принимает неизменяемый снимок профиля; сам он не выбирает хранилище и
не перечитывает настройки. CLI и `ConversationService` загружают актуальный
выбранный профиль перед каждой отправкой. Для долгоживущего Python-агента
новый снимок можно явно присвоить `agent.profile` между запросами.

## Передача модели и приоритеты

Каждый пользовательский этап получает базовую системную инструкцию, отдельное
системное сообщение `<user_profile>`, контекст выбранной стратегии, явные
слои памяти и текущий запрос. Профиль добавляется после обработки истории
стратегией и не расходует число сообщений окна. Он не записывается в историю
как системное сообщение, не сжимается в summary и не извлекается в facts.
Ответы, естественно, могут содержать сведения, заданные профилем.

Оба этапа мета-промпта получают один и тот же снимок. На первом этапе агент
переносит предпочтения в создаваемый промпт; требование вернуть только промпт
сохраняется. Служебные запросы сжатия и извлечения facts получают собственные
инструкции без профиля: им нужно обрабатывать историю, а не отвечать пользователю.

Правила, передаваемые модели:

1. Базовые системные правила и обязательный формат этапа/API сохраняют приоритет.
2. Текущий профиль задаёт предпочтения вместо устаревших сведений о стиле
   в памяти, summary, facts и прежних ответах.
3. Явную просьбу изменить язык, стиль или оформление одного ответа агент
   учитывает локально. Сохранённый профиль при этом не меняется.
4. При конфликте с ограничением профиля агент объясняет противоречие и
   предлагает подходящее решение. Факты задачи продолжает брать из памяти.

Ограничения на этом этапе задаются инструкцией модели. Программная проверка
инвариантов, конечный автомат задачи и оркестрация скиллов относятся к следующим
заданиям и здесь не реализованы. Соблюдение естественно-языковых предпочтений
зависит от модели; наличие поля `format` не заменяет API-параметр формата ответа.

## Хранение

В `data/conversations/profiles.sqlite3` отдельно хранятся таблицы `profiles`
и `profile_selection`. Форматы истории и существующей базы памяти не меняются.
Удаление диалога убирает его выбор, сохраняя сами профили. Очистка истории или
рабочей памяти не меняет профиль. Обычные сообщения не создают и не редактируют
профили автоматически; повреждение базы показывается как ошибка, а не как
незаметное отключение персонализации.

Приложение рассчитано на одного локального пользователя с несколькими
профилями под разные задачи. Переключение профиля не переключает пользователя:
долговременная память остаётся общей, рабочая память — отдельной для диалога.
Это не система учётных записей и не изоляция данных разных людей.

## Проверка

```shell
python -m unittest discover -s tests -v
```

Тесты без сети проверяют сохранение и выбор профилей, передачу каждого поля,
обновление настроек при следующем запросе, изоляцию диалогов, обе стадии
мета-промпта, стратегии истории, ошибки хранилища и интерфейсы. Подмена API
проверяет интеграцию, но не доказывает качество ответов настоящей LLM.

Для проверки настоящей модели выполните четыре запроса из примера CLI выше
с настроенным `API_KEY`. Первый профиль должен автоматически давать объяснения
на русском с обращением на «ты», аналогией и Python; второй — лаконичные три
пункта на «вы», Kotlin/JVM и без кода. Вопрос о рисках должен сохранить эти
особенности без повторения предпочтений. Проверьте также изменение профиля
между сообщениями, запрос с `--meta-prompt` и окно из одного сообщения.

Для сравнения влияния именно профиля используйте отдельные новые истории:
переключение внутри старого диалога сохраняет прежние ответы в его контексте.
