# MCP-контекст поддержки LLMAgent

Независимый демонстрационный сервер на официальном MCP SDK 2.2.0. Транспорт —
Streamable HTTP, адрес по умолчанию: `http://127.0.0.1:8001/mcp`.
Он читает `demo_data.json` заново при каждом вызове и не меняет данные.

## Запуск

Из каталога `SupportMCPServer` в PowerShell, с подготовленным здесь окружением:

```powershell
.\venv\Scripts\python.exe .\server.py
```

Активация окружения не требуется: команда явно использует его Python.
Если оно уже активировано, достаточно `python server.py`.
При подготовке нового окружения зависимости устанавливаются командой
`.\venv\Scripts\python.exe -m pip install -r requirements.txt`.

Запуск из корня репозитория также поддерживается:

```powershell
.\SupportMCPServer\venv\Scripts\python.exe -m SupportMCPServer.server
```

Для другого локального порта добавьте `--port 8002`. Сервер слушает только
`127.0.0.1`. Настройки `.env` не читает. Остановить сервер можно через Ctrl+C.

## Инструменты

| Инструмент | Результат |
|---|---|
| `list_users()` | `{users: [{id, name, summary}]}` |
| `list_user_tickets(user_id)` | `{tickets: [{id, user_id, subject, status}]}` |
| `get_support_context(user_id, ticket_id=null)` | `{user, ticket, demo: true}` |

`user` содержит `id`, `name`, `summary`, `environment` (`os`, `interface`,
`provider`, `model`), `settings` (`rag_enabled`, `index_status`, `mcp_enabled`)
и `observed_at`. `index_status` равен `ready` или `missing`.

`ticket` содержит `id`, `user_id`, `subject`, `status`, строку `error`, список
`attempts` и сообщения `{role, content}`. Без `ticket_id` возвращается `ticket: null`.
Статусы: `open`, `waiting_user`, `resolved`. Неизвестные идентификаторы и чужие
тикеты возвращают ошибку MCP (`isError: true`), а не пустой успешный результат.

Набор инструментов ограничен чтением. Пути к файлам не являются аргументами
инструментов. Сервер проверяет структуру JSON, уникальность идентификаторов
и владельцев тикетов; повреждённые данные дают явную ошибку.

## Демонстрационные сценарии

| Пользователь | Тикет | Наблюдение |
|---|---|---|
| `u-alex` | `t-rag-off` | RAG выключен, индекс готов |
| `u-maria` | `t-index-missing` | RAG включён, индекс отсутствует |
| `u-ivan` | `t-mcp-disabled` | Использование MCP в чате выключено |
| `u-alex` | `t-setup-resolved` | Завершённое обращение о запуске веб-чата |

У первых двух тикетов одинаковый исходный вопрос: «Почему агент не использует
документацию?» Это позволяет проверить, что ответ зависит от контекста.

Все записи синтетические. Время наблюдения фиксировано:
`2026-10-18T10:00:00+05:00`. Это данные учебного стенда, не текущая диагностика
компьютера. Значение `mcp_enabled` описывает установку демонстрационного
пользователя и не отключает данный сервер поддержки. Секреты в данных отсутствуют.

Выбор `user_id` на этом локальном стенде не является аутентификацией. Проверка
владения запрещает запрос тикета одного пользователя в контексте другого;
для реального сервиса доверенную личность должен задавать backend.

## Проверки

Из корня репозитория:

```powershell
SupportMCPServer\venv\Scripts\python.exe -m unittest discover -s SupportMCPServer/tests -v
```

Тесты проверяют различия контекста, владение тикетом, перечитывание и валидацию
JSON. Интеграционные тесты поднимают локальный HTTP-сервер на свободном порту,
выполняют discovery и вызовы всех инструментов через существующий
`llm_agent.mcp_client`, затем останавливают сервер. LLM и интернет не требуются.
