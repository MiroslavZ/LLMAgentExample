# Разбор задания «День 20: Orchestration MCP»

## Суть задания

В 20-м дне нужно показать **оркестрацию между несколькими MCP-серверами**.
Если в 19-м дне была композиция инструментов в рамках одного MCP, то здесь —
длинный флоу, где агент использует инструменты **с разных MCP**.

---

## Что требуется сделать

1. Зарегистрировать несколько MCP-серверов (минимум 2).
2. Дать агенту доступ к их tool schema.
3. Реализовать сценарий, в котором агент:
   - выбирает нужный инструмент,
   - маршрутизирует вызовы на разные MCP-серверы,
   - выполняет многошаговый флоу до финального результата.

---

## Проверка (критерии выполнения)

Нужно явно подтвердить:

- в одном пользовательском кейсе используются инструменты с разных MCP-серверов;
- порядок вызовов логически корректный;
- данные между шагами передаются без потерь;
- агент не требует ручного оркестрирования каждого шага пользователем.

---

## Ожидаемый результат по заданию

«Длинный флоу взаимодействия с несколькими MCP-серверами и инструментами».

---

## Отличие 20 дня от 19 дня

- **День 19:** цепочка нескольких tools внутри одного MCP.
- **День 20:** цепочка шагов через несколько MCP-серверов.

Иными словами, 20-й день — это масштабирование идеи 19-го:
от локального pipeline внутри одного MCP к межсерверной оркестрации.

---

## Минимальный шаблон сценария для демонстрации

1. Пользователь задаёт цель высокого уровня (например: «Собери мини-отчёт и сохрани»).
2. Агент вызывает tool на MCP-A (получение исходных данных).
3. Агент вызывает tool на MCP-B (обработка/дополнение данных).
4. При необходимости вызывает ещё один tool (например, сохранение/экспорт).
5. Возвращает итог и артефакт (файл/сводку/отчёт).

Главное в демо: показать, что агент корректно проходит весь флоу через разные MCP и не путает маршрутизацию.
