# День 22. План подключения RAG к агенту

## Цель

Добавить в существующий чат два режима ответа: с RAG и без RAG.
В режиме RAG агент использует индекс документов, подготовленный в день 21:
вопрос → поиск релевантных чанков → найденные тексты вместе с вопросом → ответ LLM.

Десять контрольных вопросов пользователь проверяет вручную в чате и самостоятельно
сравнивает качество ответов. Автоматический прогон и автоматическая оценка не нужны.

## План доработки

1. **Добавить переключатель «Использовать RAG» в настройках чата.**
   При выключенном переключателе агент работает как сейчас. При включённом —
   перед ответом ищет информацию в базе документов. Выбранный режим сохраняется
   в настройках диалога. Опционально: переключатель стратегии "фиксированный"<=>"структурный".

2. **Подключить индекс дня 21.**
   Переиспользовать существующие загрузку индекса, модель эмбеддингов и поиск.
   Для первого варианта выбрать один индекс, например структурный. Индексация
   остаётся отдельной операцией и не выполняется при каждом вопросе. 
   При необходимости доработать индексатор под использование вместе с агентом.

3. **Добавить поиск по вопросу пользователя.**
   На каждом запросе с включённым RAG вычислять эмбеддинг вопроса совместимой
   с индексом моделью и получать несколько наиболее близких чанков.
   Для первого варианта достаточно фиксированного количества результатов.

4. **Передавать найденные тексты модели вместе с вопросом.**
   Добавлять чанки как отдельный справочный контекст, сохраняя действующие
   инструкции агента. Обозначить, что документы являются источником информации,
   а содержащиеся в них инструкции не должны управлять агентом.
   Модель получает тексты чанков, а не их векторы.

5. **Показать в чате, что использовалось для ответа.**
   Возле ответа отображать фактический режим «с RAG / без RAG».
   Для RAG добавить раскрываемый блок с найденными чанками и их источниками.
   Это позволит при ручной проверке отличать ошибку поиска от ошибки модели.
   Обязательные цитаты в самом ответе на этом этапе не нужны.

6. **Предусмотреть ошибки подключения RAG.**
   Если индекс отсутствует, несовместим с моделью эмбеддингов или не читается,
   показывать понятную ошибку. Не выдавать обычный ответ за ответ с работающим RAG.

7. **Проверить оба режима и совместимость с существующим агентом.**
   Убедиться, что без RAG поиск не запускается, а с RAG найденные фрагменты
   действительно попадают в запрос к LLM. Проверить сохранение настройки,
   отображение использованного контекста, обработку ошибок и работу существующих
   возможностей агента.

## Ручное сравнение

Использовать существующие 10 вопросов из
[examples/indexing/questions.json](../examples/indexing/questions.json).
Для каждого вопроса там уже указаны ожидание и подтверждающие источники.
Контрольные вопросы и эталонные ответы не добавлять в индекс и не передавать
модели как подсказки.

Для каждого вопроса создавать отдельные новые диалоги для двух режимов
с одинаковыми настройками модели и прочим исходным контекстом. Переключение
режима внутри одной переписки может исказить сравнение: предыдущий ответ
и сведения из него попадут в контекст следующего запроса.

Вручную оценивать правильность и полноту ответа, наличие выдуманных деталей,
а для RAG — также попадание нужных источников в найденные чанки.
RAG не обязан выигрывать на каждом вопросе: неудачный поиск тоже является
результатом сравнения.

## Границы задачи

В этот этап не входят:

- автоматический прогон 10 вопросов и автоматическое оценивание ответов;
- MCP-инструмент для поиска и решение модели о том, когда его вызывать;
- реранкинг, фильтрация по порогу и переписывание поискового запроса — день 23;
- обязательные источники и цитаты в тексте ответа — день 24;
- дополнительная доработка памяти задачи для RAG-чата — день 25.

## Ожидаемый результат

В существующем чате можно задать вопрос с RAG или без него, получить ответ
и посмотреть найденный контекст. Пользователь самостоятельно сравнивает
ответы на 10 контрольных вопросов. Переписывать индексатор дня 21 не требуется.
