# Индексация документов — день 21

Самостоятельный CLI `python -m llm_agent.indexing` читает выбранные документы,
разбивает текст, вычисляет эмбеддинги на CPU и сохраняет SQLite. Ключ DeepSeek
не нужен. Чат, память диалогов и MCP не участвуют в построении индекса.
Подключение готового индекса к ответам агента описано в [RAG.md](RAG.md).

## Запуск

Используйте Python 3.11+ и окружение проекта с зависимостями `requirements.txt`:

```powershell
.\venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m llm_agent.indexing corpus
python -m llm_agent.indexing build --strategy all --cache-dir data/model-cache
python -m llm_agent.indexing stats
python -m llm_agent.indexing verify
python -m llm_agent.indexing inspect --strategy structural --limit 3
python -m llm_agent.indexing search "Как отключить персонализацию?" --cache-dir data/model-cache
python -m llm_agent.indexing compare --cache-dir data/model-cache
```

Основная модель — `intfloat/multilingual-e5-small`. Первая сборка требует загрузки
весов из Hugging Face. Последующие запуски с тем же `--cache-dir` могут использовать
`--offline`. Модель загружается один раз за команду, тексты обрабатываются батчами.
Можно задать `--revision` для закрепления конкретной ревизии.

В этой среде загрузку E5 блокирует сеть Python (`WinError 10013`). Поэтому
**реальные демонстрационные индексы построены на уже закешированной RuBERT**:

```powershell
python -m llm_agent.indexing build --strategy all --model DeepPavlov/rubert-base-cased --revision 4036cab694767a299f2b9e6492909664d9414229 --offline --batch-size 8
python -m llm_agent.indexing search "Как отключить персонализацию?" --offline
python -m llm_agent.indexing compare --offline
```

Этот запуск использует стандартный пользовательский кеш Hugging Face. На другой
машине сначала потребуется скачать указанную модель, убрав `--offline`.
RuBERT — базовая языковая модель, не специализированный sentence/retrieval encoder.
Её mean pooling даёт настоящие нейросетевые векторы, но слабое качество поиска.
Путь E5 реализован, однако реальная сборка на E5 в этой среде не проверена.
Не следует переносить приведённые ниже результаты RuBERT на E5.

`--output-dir` выбирает каталог индексов (по умолчанию `data/indexes`);
`--root` — корень корпуса; `--corpus` — JSON с явным списком файлов.
Относительные пути корпуса, индексов и отчёта отсчитываются от `--root`,
по умолчанию от корня этого репозитория. `--cache-dir` передаётся Hugging Face
как задан: относительный путь отсчитывается от текущего рабочего каталога.
`--size 350 --overlap 50 --batch-size 16` — параметры сборки по умолчанию.
`--top-k 5` задаёт число результатов поиска и глубину оценки.
Команды печатают JSON в stdout, ошибки и прогресс — в stderr; ошибка даёт код 1.

## Корпус и разбиение

Список хранится в `examples/indexing/corpus.json`: README, MCP, ORCHESTRATION,
SCHEDULING, INVARIANTS, TASK_STATE, MEMORY, PERSONALIZATION. Это 8 документов,
106 805 символов и 13 297 слов после нормализации. При условных 3 000 символов
на страницу получается **35,6 страницы**. Слова считаются разделением по пробелам;
это оценка объёма с разметкой и кодом, а не число страниц печатного PDF.
Корпус не содержит контрольные вопросы и этот отчёт.

Поддерживаются UTF-8 Markdown и TXT; BOM удаляется, CRLF/CR приводятся к LF.
Нет рекурсивного сканирования, PDF/OCR или загрузки URL. Пути вне корня,
дубликаты и неподдерживаемые расширения отклоняются; пустые файлы пропускаются.

* **Fixed:** окна до 350 токенов реального токенизатора модели с overlap 50.
  Границы выбираются независимо от заголовков, файлы не смешиваются.
* **Structural:** ATX-заголовки `#`…`######`, иерархия разделов, абзацы и fenced
  code blocks. Заголовки внутри ограждённого кода не создают разделы.
  Абзацы объединяются до 350 токенов; длинный абзац или код делится fixed с overlap.
  Между обычными разделами и абзацными группами overlap отсутствует.
  Setext-заголовки и полный CommonMark не поддерживаются.

Текст чанка — исходная подстрока нормализованного документа, без decode токенов.
`start`/`end` — индексы Unicode-символов, правая граница исключена. Это не байтовые
смещения исходного файла. `section` — первый пересекаемый раздел, `sections` — все
пересекаемые разделы; пустая строка означает преамбулу/текст без заголовков.
`chunk_id` детерминирован по источнику, хешу текста, стратегии, параметрам и границам.

## Модель и хранение

Адаптер использует Transformers AutoModel: среднее последнего скрытого слоя
с attention mask (padding исключён), затем L2-нормализацию. У RuBERT 768 координат;
у E5-small 384. Вход целиком проверяется с префиксом и специальными токенами,
лимит — до 512 токенов; скрытого truncation нет. Слишком длинный запрос отклоняется.
Для E5 используются `passage: ` и `query: ` согласно
[карточке модели](https://huggingface.co/intfloat/multilingual-e5-small).
Для RuBERT префиксы пустые.

`fixed.sqlite3` и `structural.sqlite3` содержат таблицы `documents`, `chunks`,
`metadata`. Векторы — JSON-массивы чисел, без требований к порядку байтов.
Сохранены снимки документов, SHA-256, тексты чанков, source/title/section/chunk_id,
смещения, размер, стратегия, модель, фактическая ревизия, версии библиотек,
параметры pooling/нормализации, время и настройки сборки.

Каждый индекс собирается во временный файл, проверяется и атомарно заменяет старый.
При сбое старый файл остаётся доступным. Два индекса заменяются по отдельности:
при частичном сбое повторите сборку; compare отклоняет несовместимые параметры
и разные снимки корпуса. Модель и версии библиотек при поиске должны совпадать
с сохранёнными. При обновлении зависимостей пересоберите индекс.

`verify`, `stats`, `inspect` читают SQLite без модели и сети. Проверяются структура
SQLite, число чанков, SHA снимков, offsets и текст, покрытие значимых символов,
размерность, конечность и единичная норма векторов. Токены без модели заново
не пересчитываются. `search` вычисляет только вектор вопроса и точный cosine top-k;
score — сходство, а не вероятность правильного ответа.

## Фактическое сравнение

Запуск 1 октября 2026, RuBERT revision `4036cab694767a299f2b9e6492909664d9414229`,
CPU, batch 8, размер 350 / overlap 50. Полные результаты и выдача по вопросам:
[`reports/day21/comparison.json`](reports/day21/comparison.json).

| Показатель | Fixed | Structural |
|---|---:|---:|
| Чанков | 94 | 130 |
| Токены: min / median / max | 81 / 350 / 350 | 4 / 222 / 350 |
| Среднее / p95 | 338 / 350 | 213,55 / 347 |
| Всего токенов текста чанков | 31 772 | 27 761 |
| Чанков короче 50 токенов | 0 | 3 |
| Покрыто символов | 106 805 (100%) | 106 805 (100%) |
| Повторных символов из overlap | 17 170 | 970 |
| Время chunking, с | 0,44 | 0,17 |
| Время эмбеддингов, с | 20,00 | 29,10 |
| Размер SQLite, байт | 2 158 592 | 2 830 336 |
| Hit@1 | 0% | 30% |
| Hit@5 | 20% | 40% |
| MRR@5 | 0,070 | 0,325 |

Токены таблицы не включают специальные токены модели. На этом запуске RuBERT
добавляет два специальных токена на чанк: полный объём входов — 31 960 и 28 021.
Загрузка модели заняла 5,33 с и не включена во времена эмбеддингов.
Это один последовательный запуск, не устойчивый бенчмарк скорости. Padding и
число батчей также влияют на время: меньше полезных токенов не гарантирует ускорения.

10 вопросов и эталоны записаны в `examples/indexing/questions.json` до оценки
выдачи. Релевантность требует совпадения source и присутствия точного эталонного
отрывка после нормализации пробелов. Устаревшие эталоны отклоняются.
Hit@k — доля вопросов с хотя бы одним релевантным чанком в первых k;
MRR@k — среднее обратной позиции первого релевантного чанка (0 при отсутствии).
Это узкая учебная выборка по памяти, профилям, состоянию задачи и наблюдениям;
перефразированный ответ или полезный соседний чанк автоматическая разметка может
не засчитать. Здесь не измеряется качество ответов LLM.

Примеры различий:

* В MEMORY.md fixed-чанк `[1334:3055]` начинается посреди предложения:
  «не становится подтверждённым решением автоматически». Структурный чанк,
  содержащий эту позицию, `[331:1929]` начинается с «## Слои и правила записи».
* Structural создаёт и неудобные короткие чанки: «## Реализация и ограничения»
  в MCP.md и «## Структура проекта» в README.md остаются отдельными заголовками.
  Сохранение границ разделов имеет цену; размер индекса вырос из-за числа векторов.
* Вопрос об удалении профиля: structural находит эталон на позиции 1, fixed
  не находит в top-5. Вопрос о произвольной смене этапа задачи: fixed находит
  на позиции 2, structural не находит в top-5. Победа структурного разбиения
  в среднем не означает преимущество на каждом вопросе.

Для данного корпуса structural уменьшает дублирование и улучшает измеренный
поиск, но создаёт больше чанков. Качество обеих стратегий с базовой RuBERT
недостаточно для уверенного RAG; следующим экспериментом стоит пересобрать E5
в отдельном каталоге и оценить те же заранее зафиксированные вопросы.

## Проверки

```powershell
python -m unittest discover -s tests -p "test_indexing*.py" -v
python -m llm_agent.indexing verify --strategy all
python -m unittest discover -s tests -q
```

Тесты индексатора не требуют загрузки весов: проверяют Unicode, границы, fences,
стабильность ID, corpus manifest, параметры CLI, лимиты входов, повреждение базы,
атомарную замену, поиск и оценку. Реальные веса проверены отдельной сборкой,
сравнением и повторным открытием индексов в новом процессе.
Полный набор проекта требует соседние MCPServerExample, VulnSearchMCPServerExample
и TelegramMCPServerExample; в текущем checkout этих модулей нет.

Фактический результат: 40 тестов индексатора прошли. Общий discovery: 474 теста,
469 прошли, 5 ошибок импорта отсутствующих MCP-модулей. `verify` подтвердил оба
индекса; поиск в отдельном процессе нашёл раздел «Браузер» в PERSONALIZATION.md
для вопроса «Как отключить персонализацию?». После оптимизации chunking проверено
полное совпадение заново полученных чанков с сохранёнными в обоих индексах.
