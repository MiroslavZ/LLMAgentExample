# Модели и подключения

Каталог общий для CLI и веб-чата и изначально пустой. Модели добавляются явно;
ключ в `.env` не создаёт модель и не включает облачный сервис автоматически.
Старые диалоги открываются как раньше, но перед следующим запросом нужно
выбрать модель. Смена модели сохраняет переписку, память и состояние задачи.

## Веб-интерфейс

Запуск: `python -m llm_agent.web`. В верхней панели находятся список моделей
и кнопка **Менеджер моделей** справа от него.

1. Нажмите **Добавить вручную** и укажите API ID, base URL и, если нужен, токен.
   Пустое отображаемое имя заменяется API ID.
2. Либо в разделе **Получить модели с сервера** укажите base URL и токен,
   получите список, отметьте нужные модели и нажмите **Добавить выбранные модели**.
   Загрузка списка использует `OpenAI.models.list()`; она не выполняет генерацию
   и не загружает веса перечисленных моделей. `/models` может включать embedding-модели:
   для чата выбирайте модель, поддерживающую `/chat/completions`.
3. Закройте менеджер и явно выберите модель в шапке. Каждый диалог хранит свой
   выбор, в том числе после перезапуска приложения.

Из менеджера можно изменить имя, API ID, адрес, токен, таймаут и возможности
модели или удалить запись. Пустое поле токена при редактировании сохраняет
прежний секрет; отдельный переключатель удаляет его. Повторный импорт не
дублирует пару base URL + API ID и не перезаписывает существующие настройки.
Одинаковый API ID на разных серверах — разные подключения.

После удаления выбранной модели отправка блокируется до нового выбора.
Начавшийся запрос использует снимок прежних настроек до завершения всех этапов.
Смена модели во время запроса запрещена; ранее полученные ответы сохраняют
исторические имя модели, API ID и адрес сервера.

## Параметры подключения

| Поле | Назначение |
| --- | --- |
| Отображаемое имя | Подпись в списке и у ответов |
| API ID | Точное значение `model` для сервера |
| Base URL | Корень OpenAI-совместимого API, обычно с `/v1` |
| API-токен | Необязателен для сервера без авторизации |
| Таймаут | Ожидание отдельного запроса, по умолчанию 180 секунд |
| Формат структурированного ответа | `auto` (по умолчанию), `json_schema`, `json_object` или `off` |
| Tool calling | Разрешает MCP и локальные инструменты |

Для LM Studio в этой сети: `http://192.168.1.188:1234/v1`, без токена,
модель `google/gemma-4-12b-qat`. Для DeepSeek: `https://api.deepseek.com/v1`
и ключ этого сервиса. Адрес должен вести к совместимому API; нативные API
других форматов не поддерживаются. TLS-сертификаты проверяются штатно.

Список `/models` не описывает все возможности модели. В режиме **Авто** первый
структурированный запрос использует `json_schema`. Если сервер явно отклоняет
именно этот формат как неподдерживаемый, запрос повторяется с `json_object`.
Успешный формат сохраняется для подключения и модели, в том числе между
перезапусками. Ошибки авторизации, контекста и памяти не переключают формат.
Если оба формата недоступны, приложение сообщает об ошибке без автоматического
отключения структурированного вывода.

Режимы **JSON Schema** и **JSON Object** задают формат вручную. При выборе
**Отключён** служебные JSON-запросы опираются на инструкции и проверку результата;
явный CLI-формат `object`/`schema` требует включённого структурированного вывода.
Обычный текст отправляется без `response_format`. Если сервер не поддерживает
tool calling, отключите соответствующий флаг. Качество следования протоколам
задач/RAG зависит от выбранной модели.

Локальные IP-адреса и `localhost` используют прямое HTTP-соединение, обходя
системный прокси. Для публичных адресов настройки прокси окружения сохраняются.
SDK получает служебное значение ключа для подключений без токена; облачный ключ
из окружения туда не подставляется.

## CLI

```powershell
# Посмотреть каталог без вывода токенов.
python -m llm_agent --models-list

# Только запросить список; каталог пока не меняется.
python -m llm_agent --models-discover http://192.168.1.188:1234/v1

# Добавить одну модель вручную.
python -m llm_agent --model-add google/gemma-4-12b-qat --base-url http://192.168.1.188:1234/v1 --model-name Gemma --model-structured-output auto

# Импорт всех моделей сервера; ключ читается только по явному указанию имени переменной.
python -m llm_agent --models-import https://api.deepseek.com/v1 --model-token-env API_KEY

# Новый диалог с явным выбором, затем продолжение с сохранённой моделью.
python -m llm_agent --new-conversation --model google/gemma-4-12b-qat --user "Привет"
python -m llm_agent --conversation ID --user "Продолжим"

# Изменить модель существующего диалога без генерации.
python -m llm_agent --conversation ID --model MODEL_RECORD_ID
```

`--model` принимает внутренний ID из `--models-list` или уникальный API ID.
Если один API ID есть у нескольких серверов, используйте внутренний ID.
`--model-structured-output` задаёт режим при добавлении модели; допустимы
`auto`, `json_schema`, `json_object` и `off`. Без флага выбирается `auto`.
`--data-dir` выбирает общий каталог диалогов и моделей. Веб-команда
**Продолжить в CLI** указывает на тот же каталог и использует сохранённый выбор.

## Хранение и Python API

Настройки хранятся в `models.sqlite3` внутри каталога диалогов. Токены хранятся
локально в этом файле без шифрования, исключены из Git, не попадают в JSON
диалога, отчёты или вывод CLI. Сохранённые токены не отправляются обратно
браузеру. Защищайте файл так же, как `.env`.

При открытии старый каталог автоматически обновляется. Прежний флаг
`json_mode=true` читается как `structured_output="auto"`, `false` — как `"off"`.
Кеш подтверждённого формата хранится отдельно от настроек и сбрасывается при
изменении API ID, base URL, токена или выбранного режима. Переименование модели
или изменение таймаута сохраняет кеш. Результат проверки, начатой до изменения
настроек или удаления записи, не записывается в каталог.

`LLMModel` — неизменяемая конфигурация, `ModelStore` отвечает за CRUD и импорт,
`ConversationService` связывает выбранную запись с диалогом. Основной ответ,
мета-промпт, facts, summary, инварианты, исправления JSON и подготовка RAG
используют одно подключение на ход. MCP-сервер, который самостоятельно вызывает
LLM внутри своего инструмента, по-прежнему настраивается отдельно.

```python
from pathlib import Path
from llm_agent.service import ConversationService

service = ConversationService(Path("data/conversations"))
model = service.models.import_models(
    "http://192.168.1.188:1234/v1", "", ["google/gemma-4-12b-qat"],
)[0]
conversation = service.create()
service.select_model(conversation.id, model.id)
result = service.send(conversation.id, "Привет")
print(result.turns[-1].answer)
```

Низкоуровневый `Agent(token, base_url=..., ...)` тоже поддерживает произвольный
адрес, режим `structured_output` и флаг `tools_enabled`; API ID передаётся в
`request(model=...)`. Аргумент `json_mode` сохранён для совместимости.
Для совместимости у него сохранены прежние значения DeepSeek по умолчанию.
CLI/веб через `ConversationService` эти значения не используют. Старый аргумент
`ConversationService(..., token=...)` принимается для совместимости, но не
конфигурирует каталог: ключ задаётся только в записи модели.

Справка SDK: [список моделей](https://developers.openai.com/api/reference/python/resources/models/methods/list),
[настройка Python-клиента](https://developers.openai.com/api/reference/python).
