# RAG: Query rewrite и фильтрация — дни 22–23

В настройках чата включите **Использовать RAG** и сохраните настройки либо
отправьте сообщение. Режим сохраняется для диалога; его можно менять между
вопросами. Каждый ход хранит собственный режим и найденные фрагменты, поэтому
переключение не меняет подписи старых ответов.

## Подключение индекса

По умолчанию используется `data/indexes/structural.sqlite3` относительно корня
проекта. В этом рабочем каталоге он уже собран на RuBERT по полному корпусу.
Достаточно запустить `python -m llm_agent.web` и включить RAG.
Чтобы вместо него использовать ранее подготовленный пользовательский индекс,
задайте перед запуском CLI или сервера:

```powershell
$env:RAG_INDEX_PATH = "data/my-indexes/structural.sqlite3"
python -m llm_agent.web
```

Переменную можно записать в корневой `.env`. Для другого индекса укажите его
путь, например `data/my-indexes/fixed.sqlite3`. Один процесс использует один
настроенный индекс. После изменения переменных окружения перезапустите сервер.
`RAG_CACHE_DIR` задаёт каталог кеша Hugging Face; относительный путь считается
от рабочего каталога процесса, как `--cache-dir` индексатора.

Существующий `data/my-indexes` не содержит `docs/MEMORY.md`, необходимый для
первых трёх контрольных вопросов. Стандартный корпус включает его. Чтобы
создать полный индекс отдельно от существующего, с уже закешированной RuBERT:

```powershell
python -m llm_agent.indexing build --strategy structural --model DeepPavlov/rubert-base-cased --revision 4036cab694767a299f2b9e6492909664d9414229 --offline
$env:RAG_INDEX_PATH = "data/indexes/structural.sqlite3"
```

Поиск загружает модель и ревизию из метаданных индекса, проверяет совпадение
параметров и версий библиотек. В чате загрузка работает только с локальным кешем:
модель нужно предварительно скачать при [индексации](INDEXING.md). При первом
RAG-вопросе загрузка CPU-модели может занять время; далее сервис использует её
повторно. Индекс не пересобирается при вопросе. Атомарная замена индекса видна
со следующего запроса.

## Режимы и настройки

```powershell
python main.py --new-conversation --no-rag --user "Как отключить персонализацию в браузере?"
python main.py --new-conversation --rag --user "Как отключить персонализацию в браузере?"
python main.py --new-conversation --rag --rag-filter --rag-similarity-threshold 0.35 --user "Как отключить персонализацию в браузере?"
python main.py --new-conversation --rag --rag-rewrite --rag-filter --rag-top-k-before 20 --rag-top-k-after 5 --rag-similarity-threshold 0.35 --user "Как отключить персонализацию в браузере?"
```

Без флага CLI сохраняет выбранный режим существующего диалога; у нового он
выключен. Без RAG модель эмбеддингов, индекс и служебная модель rewrite не вызываются.

В веб-настройках доступны независимые переключатели **Query rewrite · переписать
запрос** и **Filter · фильтр релевантности**, top-K до/после отбора и cosine-порог.
Параметры сохраняются при выключении общего RAG, но применяются только после
его включения. В CLI `--no-rag-rewrite` и `--no-rag-filter` отключают соответствующие
этапы; неуказанные параметры существующего диалога остаются прежними.

| Режим | Query rewrite | Filter |
|---|---|---|
| Базовый RAG | Выключен | Выключен |
| RAG + фильтр | Выключен | Включён |
| RAG + rewrite | Включён | Выключен |
| RAG + rewrite + фильтр | Включён | Включён |

По умолчанию оба этапа выключены, включая старые диалоги. Настройки K: **20 → 5**.
Требуется `1 ≤ top_k_after ≤ top_k_before`, оба значения целые. Порог должен быть
конечным числом от −1 до 1. Начальное значение **0,35** выбрано по текущему индексу
RuBERT и не является универсальным: для другого корпуса/эмбеддера его нужно
проверить заново. Выключение фильтра задаётся переключателем, а не особым порогом.

С RAG сервис получает до `top_k_before` кандидатов, при включённом фильтре оставляет
только `score ≥ similarity_threshold`, затем выбирает первые `top_k_after`.
Фильтр сохраняет порядок cosine-поиска; это не реранкер. Он не может поднять
нужный фрагмент с 12-го места в top-5. Без дополнительных этапов итоговая выдача
совпадает с прежним top-5. Тексты с метаданными передаются перед текущим вопросом.
Фрагменты отделены от инструкций
агента: модель получает правило считать их справочными данными, а не командами.
Они не добавляются в рабочую историю и не извлекаются в facts/summary.
В режиме мета-промпта один набор фрагментов используется на обоих этапах.
Ответы модели, как обычно, остаются в истории.

Query rewrite выполняет один отдельный запрос к той же модели, которая выбрана
для ответа: температура 0, максимум 200 выходных токенов, timeout 15 секунд,
без повторов, памяти, MCP, эталонов и истории. В поиск отправляется переписанный
запрос, а генератор, история и состояние задачи получают исходный вопрос.
Ошибка, пустой/оборванный ответ, длина больше 1500 символов или лимита токенизатора
эмбеддингов приводят к исходному вопросу с явной отметкой fallback. Длительность
и токены rewrite сохраняются отдельно от расхода основной генерации.

В раскрываемом блоке показаны источник, раздел, идентификатор, score и полный
текст каждого найденного чанка. Это результаты поиска, а не доказательство того,
что модель использовала каждый из них. Score — сходство, не вероятность истины.
Блок «Диагностика поиска и отбора» показывает исходный и поисковый запросы, статус rewrite,
K, порог, «найдено → прошло → передано», время и кандидатов с причинами отсева.
У каждого хода свой снимок настроек: изменение переключателя не меняет прошлые ответы.
Полный список кандидатов сохраняется для диагностики, но в prompt попадают только
финальные чанки. Когда все кандидаты отсеяны, RAG остаётся включённым и модель
получает сообщение об отсутствии подходящих фрагментов. Отброшенные чанки не
добавляются обратно для заполнения top-K; пустой результат сохраняется и читается.
При ошибке поиска генерация ответа не запускается; ошибка явно отображается в чате.
Сохранённые фрагменты доступны и при последующей ошибке генерации.

## Контрольные вопросы и сравнение

Набор из 10 вопросов с ожиданиями и источниками:
[`examples/indexing/questions.json`](../examples/indexing/questions.json).
Скрипт не добавляет этот файл в индекс и не передаёт ожидания или evidence модели.
Для независимой оценки нужно исключить материалы прошлых проверок и примеры
контрольных вопросов из корпуса. В текущем снимке такие материалы обнаружены;
подробности приведены в отчёте. Индекс при этой доработке не пересобирался.

Для каждого вопроса создайте отдельные новые диалоги с одинаковыми моделью,
температурой, системным промптом, памятью и профилем. Отключите MCP и режим задачи,
чтобы они не давали дополнительный источник ответа. В одном диалоге включите
базовый RAG без rewrite/фильтра, в другом RAG + rewrite + фильтр. Для понимания
вклада каждого этапа добавьте режимы только с фильтром и только с rewrite.
Сравнение дня 23 выполняется с RAG в обоих случаях. Смена режима внутри общей
переписки делает сравнение нечестным: ответ из базы уже остаётся в истории.

Запишите ответы и оценки в [отчёт сравнения](DAY23_COMPARISON.md):
0 — неверно или ответ отсутствует; 1 — частично верно; 2 — верно и достаточно полно.
Отдельно отметьте выдуманные детали и наличие ожидаемого отрывка среди top-5.
Сравните сумму баллов из 20 и число ответов с выдумками. Ошибка подключения —
сбой запуска, а не оценка качества модели.

Для воспроизводимого прогона есть `python -m llm_agent.rag_evaluation --help`:
он использует отдельное временное хранилище с пустой памятью, новыми диалогами
и отключёнными MCP/профилями, проверяет источники эталонов и фиксирует индекс.
JSON-отчёт содержит ответы, контекст и метрики попадания `source + quote`;
оценки правильности и выдумок оставляются для ручной проверки.

Фактическая локальная проверка фильтра и недоступность API в среде разработки
описаны в отчёте. Сравнение качества ответов и эффект rewrite пока не измерены.
У RuBERT ограниченное качество retrieval; проверка кода тестами не заменяет
сравнение ответов LLM. Отдельный реранкер и обязательные цитаты здесь не добавлены;
обязательные цитаты и усиление поведения при недостатке данных относятся к дню 24.
