# Первый RAG-запрос — день 22

В настройках чата включите **Использовать RAG** и сохраните настройки либо
отправьте сообщение. Режим сохраняется для диалога; его можно менять между
вопросами. Каждый ход хранит собственный режим и найденные фрагменты, поэтому
переключение не меняет подписи старых ответов.

## Подключение индекса

По умолчанию используется `data/indexes/structural.sqlite3` относительно корня
проекта. В этом рабочем каталоге он уже собран на RuBERT по полному корпусу.
Достаточно запустить `python -m llm_agent.web` и включить RAG.
Чтобы вместо него использовать ранее подготовленный пользовательский индекс,
задайте перед запуском CLI или сервера:

```powershell
$env:RAG_INDEX_PATH = "data/my-indexes/structural.sqlite3"
python -m llm_agent.web
```

Переменную можно записать в корневой `.env`. Для другого индекса укажите его
путь, например `data/my-indexes/fixed.sqlite3`. Один процесс использует один
настроенный индекс. После изменения переменных окружения перезапустите сервер.
`RAG_CACHE_DIR` задаёт каталог кеша Hugging Face; относительный путь считается
от рабочего каталога процесса, как `--cache-dir` индексатора.

Существующий `data/my-indexes` не содержит `docs/MEMORY.md`, необходимый для
первых трёх контрольных вопросов. Стандартный корпус включает его. Чтобы
создать полный индекс отдельно от существующего, с уже закешированной RuBERT:

```powershell
python -m llm_agent.indexing build --strategy structural --model DeepPavlov/rubert-base-cased --revision 4036cab694767a299f2b9e6492909664d9414229 --offline
$env:RAG_INDEX_PATH = "data/indexes/structural.sqlite3"
```

Поиск загружает модель и ревизию из метаданных индекса, проверяет совпадение
параметров и версий библиотек. В чате загрузка работает только с локальным кешем:
модель нужно предварительно скачать при [индексации](INDEXING.md). При первом
RAG-вопросе загрузка CPU-модели может занять время; далее сервис использует её
повторно. Индекс не пересобирается при вопросе. Атомарная замена индекса видна
со следующего запроса.

## Два режима

```powershell
python main.py --new-conversation --no-rag --user "Как отключить персонализацию в браузере?"
python main.py --new-conversation --rag --user "Как отключить персонализацию в браузере?"
```

Без флага CLI сохраняет выбранный режим существующего диалога; у нового он
выключен. Без RAG модель эмбеддингов и индекс не загружаются.

С RAG сервис вычисляет вектор исходного вопроса, выбирает cosine top-5 и передаёт
тексты с метаданными перед текущим вопросом. Фрагменты отделены от инструкций
агента: модель получает правило считать их справочными данными, а не командами.
Они не добавляются в рабочую историю и не извлекаются в facts/summary.
В режиме мета-промпта один набор фрагментов используется на обоих этапах.
Ответы модели, как обычно, остаются в истории.

В раскрываемом блоке показаны источник, раздел, идентификатор, score и полный
текст каждого найденного чанка. Это результаты поиска, а не доказательство того,
что модель использовала каждый из них. Score — сходство, не вероятность истины.
При ошибке поиска запрос к LLM не отправляется; ошибка явно отображается в чате.
Сохранённые фрагменты доступны и при последующей ошибке генерации.

## Контрольные вопросы и ручное сравнение

Набор из 10 вопросов с ожиданиями и источниками:
[`examples/indexing/questions.json`](../examples/indexing/questions.json).
Вопросы и эталонные ответы не включаются в индекс или промпт.

Для каждого вопроса создайте два новых диалога с одинаковыми моделью,
температурой, системным промптом, памятью и профилем. Отключите MCP и режим задачи,
чтобы они не давали дополнительный источник ответа. В одном диалоге включите
RAG, в другом выключите. Смена режима внутри общей переписки делает сравнение
нечестным: ответ из базы уже остаётся в истории.

Запишите ответы и оценки в [таблицу сравнения](DAY22_COMPARISON.md):
0 — неверно или ответ отсутствует; 1 — частично верно; 2 — верно и достаточно полно.
Отдельно отметьте выдуманные детали и наличие ожидаемого отрывка среди top-5.
Сравните сумму баллов из 20 и число ответов с выдумками. Ошибка подключения —
сбой запуска, а не оценка качества модели.

Реранкинг, пороги, query rewrite и обязательные цитаты остаются на дни 23–24.
У RuBERT из дня 21 ограниченное качество retrieval; RAG не обязан улучшить каждый
ответ. Проверка передачи контекста тестами не заменяет сравнения ответов LLM.
