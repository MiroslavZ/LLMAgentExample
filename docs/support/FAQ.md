# FAQ поддержки LLMAgent

LLMAgent — продукт из пакета `llm_agent`: Python-агент с CLI, веб-чатом,
каталогом моделей, RAG и подключением MCP. Ниже описаны настройки именно
этого продукта. Отдельный ассистент поддержки использует эту документацию,
но его собственное подключение к модели и база обращений настраиваются отдельно.
Наличие проблемы в установке пользователя не означает такую же проблему
у сервиса поддержки.

Команды выполняются из корня проекта в окружении с установленными зависимостями.
В примерах `ID` нужно заменить на идентификатор своего диалога. При отправке
сообщений в LLMAgent модель должна быть добавлена в каталог и выбрана в диалоге.

## 1. Почему каталог моделей пустой и сообщение не отправляется?

Каталог LLMAgent изначально пустой. Значения `API_KEY`, `MODEL` или адрес
провайдера в `.env` сами по себе не создают запись модели. Откройте
**Менеджер моделей**, добавьте модель вручную либо получите список с сервера,
отметьте нужную модель и добавьте её в каталог. Затем явно выберите её в шапке
нужного диалога. Нужен точный API ID модели и адрес OpenAI-совместимого API.

Проверить каталог без генерации можно командой
`python -m llm_agent --models-list`. Если запись существует, но выбранная модель
удалена или выбор пуст, выберите доступную запись заново. Каждый диалог хранит
свой выбор. Загрузка списка моделей не скачивает веса и не проверяет качество
генерации. Для чата нужна модель с поддержкой `/chat/completions`.

Основание: [каталог моделей](../LLM_MODELS.md),
`ConversationService.get_model` в [service.py](../../llm_agent/service.py).

## 2. Почему сервис модели отклонил API-ключ?

Сообщение «Сервис модели отклонил API-ключ» относится к подключению выбранной
модели LLMAgent. В **Менеджере моделей** проверьте адрес, API ID и токен именно
этой записи. Ключ другого провайдера или изменение только `.env` не заменяет
сохранённый токен модели. Для DeepSeek в каталоге используется адрес
`https://api.deepseek.com/v1` и ключ этого сервиса.

При редактировании пустое поле токена сохраняет прежний секрет; отдельный
переключатель удаляет его. После сохранения повторите запрос. Не отправляйте
сам ключ в сообщение поддержки: достаточно текста ошибки, имени провайдера
и признака того, что ключ настроен. Ошибка авторизации не доказывает сетевой
сбой и не исправляется пересборкой RAG-индекса.

Основание: [параметры подключения](../LLM_MODELS.md),
`_friendly_error` в [service.py](../../llm_agent/service.py).

## 3. Что проверить при ошибке подключения к сервису модели?

Откройте запись выбранной модели в **Менеджере моделей**. Проверьте её base URL,
порт и доступность сервера с машины, где работает LLMAgent. `localhost`
указывает на эту машину. Если это ваш локальный сервер, он должен быть запущен
и предоставлять OpenAI-совместимый API. Для облачного подключения нужен
доступ к адресу провайдера; локальный сервер не требуется.

**Получить модели с сервера** помогает проверить адрес и доступ к `/models`,
но успешный список ещё не гарантирует успешный `/chat/completions`. Если
сообщение говорит о таймауте, повторите запрос и проверьте настройку таймаута
модели. Если сервис ограничил число запросов, повторите позже. Сохраняйте
точный текст ошибки: отсутствие соединения, отклонённый ключ и лимит запросов
требуют разных действий. По одному общему описанию «не работает» причину
установить нельзя.

Основание: [модели и подключения](../LLM_MODELS.md),
`_friendly_error` в [service.py](../../llm_agent/service.py).

## 4. Почему агент не ищет в документации, хотя индекс уже собран?

У нового диалога LLMAgent RAG выключен. Наличие SQLite-индекса не включает
поиск автоматически. В настройках нужного диалога включите **Использовать RAG**
и сохраните настройки. В CLI: `python main.py --conversation ID --rag`.
Режим сохраняется для диалога; у другого диалога он может быть выключен.

При выключенном RAG поиск и embedding-модель не вызываются. Для продолжений
вроде «а как её очистить?» можно дополнительно включить **Query rewrite**
или `--rag-rewrite`: поиск получит самостоятельный вопрос с учётом контекста.
Rewrite и фильтр релевантности — отдельные настройки; сами по себе они
не заменяют общий переключатель RAG.

Основание: `ContextSettings` в [models.py](../../llm_agent/models.py),
`ConversationService.send` в [service.py](../../llm_agent/service.py).

## 5. Что означает «RAG: индекс отсутствует или повреждён»?

LLMAgent не смог прочитать настроенный SQLite-индекс. Проверьте `RAG_INDEX_PATH`,
существование файла и доступ к нему. Без явного пути используется
`data/indexes/structural.sqlite3` относительно корня проекта. Наличие Markdown
в `docs/` не означает, что индекс существует: он строится отдельной командой,
а не при каждом вопросе.

Проверка стандартного структурного индекса без модели и сети:
`python -m llm_agent.indexing verify --strategy structural --output-dir data/indexes`.
Для своего индекса подставьте его каталог. Если индекса нет, подготовьте JSON
с явным списком нужных файлов в поле `files` и соберите его через
`python -m llm_agent.indexing build`, указав `--corpus`, `--strategy structural`,
`--model` и `--output-dir`. Указанные пути должны соответствовать вашей установке.
Для нового корпуса выбирайте отдельный каталог: сборка заменяет индекс
с тем же именем в выбранном каталоге. Затем задайте путь к полученному файлу
в `RAG_INDEX_PATH` и перезапустите приложение после изменения окружения.

Основание: `Retriever` в [rag.py](../../llm_agent/rag.py),
[CLI индексатора](../../llm_agent/indexing/__main__.py).

## 6. Почему RAG не может загрузить локальную модель, хотя чат работает?

Для RAG LLMAgent использует отдельную локальную embedding-модель, вычисляющую
векторы документов и вопросов. Она не является чат-моделью из менеджера.
Работа ответа через облачный API не подтверждает наличие embedding-модели.

Проверьте зависимости и каталог `RAG_CACHE_DIR`. Поиск восстанавливает модель
и ревизию из метаданных индекса; по умолчанию загрузка идёт только из локального
кеша. Предварительно загрузите нужную embedding-модель при индексации.
`--offline` подходит лишь при наличии всех файлов модели в выбранном кеше.
`--cache-dir` индексатора и `RAG_CACHE_DIR` поиска должны указывать на нужный кеш.
Если сообщение говорит, что модель или версии библиотек не совпадают с индексом,
пересоберите индекс с текущими зависимостями. Смена чат-модели не перестраивает
RAG-индекс и не заменяет его embedding-модель.

Основание: `Retriever.retrieve` в [rag.py](../../llm_agent/rag.py),
[адаптер эмбеддингов](../../llm_agent/indexing/embeddings.py).

## 7. Почему RAG отвечает «Не знаю», хотя показывает найденные фрагменты?

Найденный фрагмент может быть похож на вопрос, но не содержать ответа.
LLMAgent проверяет достаточность контекста: при пустой финальной выдаче или
лучшем score ниже настроенного порога основной ответ модели не вызывается.
Проверка порога действует и при выключенном фильтре. Модель также может
сообщить о недостатке доказательств при непустой выдаче.

Откройте **Найденные фрагменты RAG** и **Диагностику поиска и отбора**.
Проверьте поисковый запрос, источники, тексты и порог. Убедитесь, что нужный
документ включён в корпус и индекс пересобран после его изменения. Уточните
вопрос; для продолжения разговора включите Query rewrite. Значение score
показывает сходство, а не вероятность правильности ответа. Снижение порога
не добавляет отсутствующую информацию в документацию.

Основание: [проверка RAG-ответов](../../llm_agent/rag_answer.py),
[генерация ответа](../../llm_agent/agent.py), [поиск](../../llm_agent/rag.py).

## 8. Почему Get tools работает, но агент не вызывает MCP-инструменты?

**Get tools** проверяет подключение и запрашивает список инструментов.
Эта кнопка не включает их использование в диалоге. Откройте подключение
в **MCP**, включите **Использовать в чате** и нажмите **Сохранить MCP**.
Настройка подключения общая для диалогов. Дополнительно проверьте, что
у выбранной чат-модели в **Менеджере моделей** включён **Tool calling**
и сам сервер модели поддерживает вызовы инструментов.

В режиме задачи до утверждения плана инструменты не вызываются: сначала
обсуждается и утверждается план. После этого модель выбирает инструменты
для подходящего запроса; получение списка не обязывает её вызывать каждый
инструмент. Если RAG остановил ход из-за недостатка документального контекста,
до основного цикла инструментов ход также может не дойти.

Основание: [панель MCP](../../llm_agent/web/mcp.py),
`_complete_with_tools` и проверка `use_tools` в [agent.py](../../llm_agent/agent.py).

## 9. Как подключить доступный MCP endpoint и проверить ошибку соединения?

LLMAgent подключается к уже работающему MCP-серверу через **Streamable HTTP**.
В **MCP → Добавить MCP** укажите имя и фактический URL endpoint, включите
**Использовать в чате**, сохраните и нажмите **Get tools**. Например,
`http://127.0.0.1:8000/mcp` подходит только если ваш сервер действительно
запущен на этом адресе. Для удалённого сервера нужен HTTPS. Агент не запускает
MCP-сервер автоматически; наличие отдельного сервера в репозитории не требуется.

Если сервер требует Bearer-токен, укажите **имя переменной окружения**,
например `MCP_ACCESS_TOKEN`. Сам токен задайте в окружении процесса или `.env`
агента и перезапустите приложение. Для сервера без авторизации поле оставьте
пустым. Токен модели и токен доступа к MCP — разные настройки.

При HTTP 404 проверьте именно путь endpoint; при 401/403 — токен и его права;
при отсутствии соединения — адрес, запуск сервера и сеть; при таймауте —
доступность и время ответа сервера. Если соединение есть, но tools не поддерживаются,
нужен MCP-сервер с инструментами. Пустой список tools означает, что сервер
не предоставил инструменты, а не что они автоматически подключены из другого места.

Основание: [валидация URL](../../llm_agent/mcp_config.py),
`_session` и `get_tools` в [mcp_client.py](../../llm_agent/mcp_client.py).

## 10. Куда пропали история и выбранная модель после запуска CLI или веба?

CLI и веб LLMAgent используют общий каталог диалогов, по умолчанию
`data/conversations`. Проверьте, что открыт прежний ID диалога и обе команды
используют одинаковый `--data-dir`. Список доступен через
`python main.py --list-conversations`. Новый диалог имеет собственную историю
и настройки; он не является продолжением прежнего.

Смена модели в существующем диалоге сохраняет переписку, память и состояние
задачи. Окно контекста или сжатие могут убрать старые сообщения из запроса
к модели, но не удаляют полную ленту общего диалога. Если сообщения видны,
а модель не учитывает ранние детали, проверьте стратегию контекста и размер
окна. Для ошибки чтения истории проверьте доступ к каталогу данных; не удаляйте
файлы диалога как способ исправить подключение к модели.

Основание: [каталог моделей](../LLM_MODELS.md),
[хранилище диалогов](../../llm_agent/storage.py),
[стратегии контекста](../../llm_agent/context_strategy.py).

## 11. Чем отличаются рабочая, долговременная память и память RAG-диалога?

Рабочая память LLMAgent хранит явные записи для одного диалога.
Долговременная память — общий словарь для диалогов одного каталога данных.
Откройте **Память агента**, выберите слой, ключ и значение и сохраните запись.
Обычная просьба «запомни» сама по себе не записывает эти два слоя.
В CLI доступны `--memory-set working КЛЮЧ ЗНАЧЕНИЕ`,
`--memory-set long_term КЛЮЧ ЗНАЧЕНИЕ` и `--memory-show` с выбранным диалогом.

При включённом RAG отдельно обновляется **Память диалога**:
цель, уточнения, ограничения и термины из сообщений пользователя.
Исправления и отмены этих сведений задаются обычными сообщениями.
Выключение RAG сохраняет эту память, но прекращает её обновление и передачу
модели. `--memory-clear-working` очищает только явную рабочую память;
оно не удаляет историю, долговременные записи и память RAG-диалога.
Новый диалог начинает с пустой рабочей и RAG-памятью, сохраняя доступ
к общим долговременным записям. Это локальное хранилище, а не изоляция аккаунтов.

Основание: [явная память](../../llm_agent/memory.py),
[память RAG-диалога](../../llm_agent/rag_dialogue.py),
`ConversationService.send` в [service.py](../../llm_agent/service.py).

## 12. Почему задача не продолжает выполнение после сообщения «согласен»?

В режиме задачи LLMAgent предложенный план остаётся на этапе `planning`
до явного утверждения. Согласие текстом не заменяет кнопку **Утвердить план**
или команду `python main.py --conversation ID --task-approve`.
Сначала просмотрите план, затем утвердите его и нажмите **Продолжить шаг**
либо выполните `python main.py --conversation ID --task-continue`.

Один запрос выполняет один шаг. На паузе сначала нажмите **Возобновить**
или используйте `--task-resume`. После перепланирования новый план нужно
утвердить заново. Если шаг отклонён из-за правил проекта, проверьте
**Инварианты агента** и указанную причину: модель не может изменить эти правила
обычным сообщением. Сетевой сбой или ошибка протокола не означают завершение
шага; проверяйте сохранённое состояние задачи.

Основание: [состояние задачи](../TASK_STATE.md),
[инварианты](../INVARIANTS.md), [переходы](../../llm_agent/task_state.py).
