# Материалы поддержки LLMAgent

[FAQ.md](FAQ.md) описывает поведение продукта LLMAgent, а не устройство
отдельного сервиса поддержки. Настройки пользователя, сообщённые через MCP,
служат контекстом обращения; они не меняют настройки сервиса поддержки.

## Корпус знаний

[corpus.json](corpus.json) — явный список файлов для существующего индексатора.
Пути в нём отсчитываются от корня репозитория. Ссылки внутри Markdown
не означают включения целевого файла в индекс: загрузчик читает только список
`files`, без рекурсивного обхода `docs/`.

| Источник | Содержание |
| --- | --- |
| `docs/support/FAQ.md` | Двенадцать вопросов: каталог и подключение моделей, RAG, индекс, эмбеддинги, MCP, история, память и выполнение задач |
| `docs/LLM_MODELS.md` | Актуальный каталог моделей, выбор для диалога, возможности модели и настройки подключения |
| `docs/TASK_STATE.md` | Этапы задачи, утверждение плана, пауза, ошибки и сохранение прогресса |

FAQ сверяется с исходниками `llm_agent`, прежде всего с `service.py`, `rag.py`,
`mcp_client.py`, `mcp_config.py`, `models.py`, `memory.py`, `rag_dialogue.py`
и панелями веб-интерфейса. Ранее написанные документы не изменяются.
Команды отправки сообщений из исходных руководств предполагают, что модель
уже добавлена и выбрана; одного ключа в `.env` для этого недостаточно.

## Что намеренно не входит в индекс

- `TASKS.md`, `CHAT.md`, `LECTURE.md`, `SOLUTIONS.md`, планы дней, отчёты,
  `docs/evaluation/`, эталонные вопросы и чужие решения: это материалы обучения
  и проверки, а не пользовательская база знаний продукта.
- Корневой `README.md`, `docs/MCP.md`, `docs/ORCHESTRATION.md`:
  содержат сценарии с отсутствующим `MCPServerExample`.
  Настройка реально доступного MCP endpoint описана в FAQ по текущему клиенту.
- `docs/MEMORY.md` и `docs/PERSONALIZATION.md`: содержат устаревшие утверждения,
  что автомат задач и проверки инвариантов ещё не реализованы. Текущие правила
  памяти изложены в FAQ по коду.
- `docs/INVARIANTS.md`: завершается устаревшим утверждением, что подтверждение
  плана относится к следующему заданию. Текущий порядок описан в `TASK_STATE.md`.
- `docs/SCHEDULING.md`: подготовка описана через один `API_KEY`, без обязательного
  добавления и выбора модели в нынешнем каталоге; планировщик не нужен базовому
  сценарию поддержки.
- `docs/RAG.md` и `docs/INDEXING.md`: смешивают пользовательские инструкции
  с результатами учебных прогонов и утверждениями о старых локальных индексах
  и кешах. Для поддержки в FAQ включены проверенные настройки, ошибки и
  диагностика без предположения о наличии индекса на машине пользователя.
- Пользователи и тикеты JSON, история чатов и секреты: оперативный контекст
  получается через MCP, а не включается в общий индекс документации.
- Этот README: устройство корпуса и сценарии проверки не должны подменять
  ответ пользователю о продукте.

При обновлении продукта нужно перепроверить FAQ и пересобрать отдельный индекс
поддержки. Изменение manifest само по себе не меняет уже построенный индекс.

## Сценарии для проверки

Это проверки поведения, а не готовые ответы для индексирования. Конкретные ID
пользователей и тикетов задаются тестовыми данными MCP.

1. Один вопрос «Почему не работает агент?» при разных контекстах: пустой
   каталог, отсутствие выбранной модели и недоступный адрес провайдера.
   Ответ должен различать эти состояния и ссылаться на соответствующую инструкцию.
2. «Почему нет ответов по документации?» при выключенном RAG и при включённом
   RAG с отсутствующим индексом. В первом случае требуется включить режим,
   во втором — проверить путь и наличие индекса.
3. «Почему не вызывается инструмент?» при отключённом использовании MCP
   в чате, выключенном Tool calling модели и ошибке соединения с endpoint.
   Получение списка инструментов и их использование нужно различать.
4. Повторный вопрос по тикету после уже выполненной проверки: учитывать
   предыдущие попытки и не выдавать их за новое решение.
5. Уточнение «а как это проверить?» в том же обращении: сохранить тему,
   выбранного пользователя и тикет; при нехватке фактов запросить уточнение.
6. Вопрос о функции, которой нет в документации: сообщить о недостатке данных,
   не обещать выполненное изменение настроек или передачу обращения человеку.
