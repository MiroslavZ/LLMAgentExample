# Демо ассистента для работы с файлами — день 34

Существующий агент получает цель обычным сообщением, сам находит исходники через
MCP, читает их и сохраняет результат. В примере два сценария: отчёт об использовании
`ApiClient` и исправление документации по коду. Каждый требует сопоставить несколько
файлов; новый агент и отдельный интерфейс не нужны.

## Подготовка

Все команды ниже выполняются **из корня LLMAgentExample** в PowerShell.
Используйте активированное Python-окружение проекта. Если зависимости ещё не
установлены, выполните:

```powershell
python -m pip install -r requirements.txt
python -m pip install -r LocalMCPServer/requirements.txt
python examples/file_assistant/prepare_demo.py
```

Подготовка копирует `baseline/` в `data/file-assistant-demo/project/`:

```text
project/
  client.py       ApiClient: timeout=30 секунд, retries=3
  service.py      создание клиента и вызов get_record
  worker.py       передача клиента сервису и создание клиента при запуске
  README.md       устаревшие значения timeout=5, retries=1
  docs/README.md  существующий каталог для отчёта
```

Клиент возвращает данные из памяти: HTTP, ожидание и retry-механизм отсутствуют.
`timeout` и `retries` — настройки будущего транспорта. Исправленная документация
должна сохранять это различие. Для демонстрации не нужны внешние API, кроме
подключения самого агента к выбранной LLM.

Повторная подготовка **без `--reset` не перезаписывает** существующую копию.
Исходный `baseline/` агенту не предоставляется. Маркер владельца лежит рядом с
`project/`, за пределами корня файлового MCP-сервера.

## Сервер и обычный веб-чат

В первом терминале:

```powershell
python -m LocalMCPServer.server --project-root data/file-assistant-demo/project --port 8001
```

Во втором терминале:

```powershell
python -m llm_agent.web
```

Откройте [локальный чат](http://127.0.0.1:8080). В новом обычном диалоге:

1. Выберите настроенную модель с поддержкой tool calling. Если каталог пуст,
   добавьте подключение через **Менеджер моделей** по [инструкции моделей](../../docs/LLM_MODELS.md).
2. В панели **MCP** добавьте `http://127.0.0.1:8001/mcp`, оставьте поле токена пустым,
   включите **Использовать в чате** и проверьте **Get tools**. Должны быть доступны
   `list_files`, `search_text`, `read_file`, `create_file`, `edit_file`.
3. Для наглядности оставьте включённым только этот MCP-сервер и выключите
   **Использовать RAG**. Встроенные правила проекта и пользовательский профиль,
   если они настроены, по-прежнему действуют.
4. Отправьте цели ниже. Для второго сценария можно создать новый обычный диалог
   с теми же настройками. Режим «Начать задачу» для демонстрации не требуется.

## Две цели для агента

**Сценарий 1 — исследование нескольких файлов и создание отчёта:**

> Найди все использования ApiClient в исходном коде проекта. Сохрани отчёт в
> docs/api-usage.md: для каждого места укажи файл, строку и роль использования,
> затем кратко объясни, как клиент проходит от worker к сервису. Исходный код
> не меняй. Если отчёт уже существует, актуализируй его без повторяющихся разделов.

Здесь пользователь задаёт артефакт результата, а файлы для исследования и порядок
операций выбирает модель. В трассе должны быть видны поиск, чтение `client.py`,
`service.py`, `worker.py` и создание либо изменение отчёта.

**Сценарий 2 — актуализация документации по реализации:**

> Сверь README с текущим кодом проекта и обнови его: опиши реальные настройки
> ApiClient по умолчанию и то, как клиент используют сервис и worker. Сохрани
> полезные существующие разделы. Меняй только README; исходники уже правильные.
> Если описание уже соответствует коду, не добавляй повторную информацию.

Ожидается, что агент найдёт расхождение `5/1` с `30/3` в коде, исправит README и
покажет результат операции с diff. Проверьте, что он не приписал учебному клиенту
реальные HTTP-запросы или retry-механизм.

## Те же сценарии через CLI

Посмотрите идентификатор уже добавленной модели и подставьте его в переменную:

```powershell
python -m llm_agent --models-list
$demoModel = 'ID_ИЗ_КАТАЛОГА'
```

`--model` принимает внутренний ID записи или уникальный API ID. Он выбирает
подключение из каталога; `--base-url` используется отдельно при добавлении модели,
а не при отправке сообщения.

```powershell
python -m llm_agent --new-conversation --model $demoModel --no-rag --mcp-url http://127.0.0.1:8001/mcp --mcp-token-env='' --user 'Найди все использования ApiClient в исходном коде проекта. Сохрани отчёт в docs/api-usage.md: для каждого места укажи файл, строку и роль использования, затем кратко объясни, как клиент проходит от worker к сервису. Исходный код не меняй. Если отчёт уже существует, актуализируй его без повторяющихся разделов.'

python -m llm_agent --new-conversation --model $demoModel --no-rag --mcp-url http://127.0.0.1:8001/mcp --mcp-token-env='' --user 'Сверь README с текущим кодом проекта и обнови его: опиши реальные настройки ApiClient по умолчанию и то, как клиент используют сервис и worker. Сохрани полезные существующие разделы. Меняй только README; исходники уже правильные. Если описание уже соответствует коду, не добавляй повторную информацию.'
```

Форма `--mcp-token-env=''` передаёт пустое значение надёжнее в разных версиях
PowerShell. Токен MCP не требуется. Настройка `--mcp-url` сохраняет подключение с
ID `cli` для CLI и веб-чата; остальные включённые серверы автоматически не отключаются.

## Проверка и повторение

Результаты лежат в `data/file-assistant-demo/project/`. Посмотрите сохранённые
`docs/api-usage.md`, `README.md` и журнал MCP-вызовов в чате. Можно дополнительно
проверить структуру результатов без обращения к модели:

```powershell
python examples/file_assistant/prepare_demo.py --check
```

Код возврата `0` означает, что отчёт непустой и упоминает три исходника, README
изменён и содержит имена параметров рядом с числами `30` и `3`, а исходники
побайтно совпадают с baseline. Код `1` означает невыполненную проверку или ошибку.
**Это не оценка полноты найденных использований, правильности номеров строк или
семантики документации.** Эти свойства нужно сопоставить с кодом. Проверка чистого
baseline закономерно завершается с `1`: агент ещё не выполнил обе задачи.

Для повторного прогона остановите MCP-сервер через `Ctrl+C`, выполните явный сброс,
затем снова запустите сервер и создайте новые диалоги:

```powershell
python examples/file_assistant/prepare_demo.py --reset
python -m LocalMCPServer.server --project-root data/file-assistant-demo/project --port 8001
```

Сбрасывается только фиксированная копия `data/file-assistant-demo/project/`.
Скрипт не принимает произвольный `--target`, проверяет маркер и отказывается от
сброса при symlink/junction. Отчёт и правки README при сбросе удаляются; если их
нужно сохранить для демонстрации, скопируйте их заранее в другое место.

Запуск целей в чате или CLI обращается к реальной выбранной модели; её ответы
могут различаться. Подготовка, `--check` и тесты со сценарным подставным ответом
не доказывают качество живого запуска. Для сдачи повторите обе цели с реальной
моделью, проверьте трассу и артефакты; само видео снимается отдельно.
